## Overview

Hypergredient primitives are canonical JSON representations of every
cosmeceutical ingredient in the `HypergredientDatabase`.  They are
generated by a three-stage automated pipeline:

| Stage | Script | Workflow |
|---|---|---|
| **1 – Generate** | `generate_primitives.py` | `reusable_hypergredient_primitives.yml` |
| **2 – Refine** | `refine_primitives.py` | `hypergredient_primitives_refine.yml` |
| **3 – Publish** | `publish_primitives.py` | `hypergredient_primitives_publish.yml` |

A fourth utility validates the output:

| Utility | Script |
|---|---|
| **Validate** | `validate_primitives.py` |

All scripts live in `examples/python/`.

## Folder Structure

After a full pipeline run, the output tree looks like this:

```
metop/
└── hyping/
    ├── index.json                          ← global ingredient index
    ├── run_manifest.json                   ← last run metadata + stats
    ├── .gitkeep
    │
    ├── astaxanthin/                        ← one directory per ingredient (slug)
    │   ├── raw/
    │   │   └── astaxanthin.json            ← Stage 1 output
    │   ├── refined/
    │   │   └── astaxanthin.json            ← Stage 2 enriched primitive
    │   ├── scored/
    │   │   └── astaxanthin_scored.json     ← Stage 2 benchmark overlay
    │   └── reports/
    │       └── astaxanthin_report.md       ← Stage 3 human-readable report
    │
    ├── bakuchiol/
    │   └── ...
    │
    └── (one directory per ingredient)
```

The `{{hyper-ingredient-name}}` directory name is a deterministic URL-safe
slug of the ingredient's display name (lower-cased, non-alphanumeric
characters replaced with `-`).

```
              │  • validate_primitives.py (full)           │
              │  • test_primitives_pipeline.py             │
              │  • upload artifact: refined                │
              └──────────────────────┬─────────────────────┘
                                     │  artifact: metop-hyping-primitives-refined
                                     ▼
              ┌────────────────────────────────────────────┐
              │  hypergredient_primitives_publish.yml      │
              │  (Stage 3: Publish + PR)                   │
              │                                            │
              │  • download refined artifact               │
              │  • publish_primitives.py                   │
              │  • validate_primitives.py (full)           │

              │  • commit to PR branch                     │
              │  • open / update pull request              │
              │  • upload artifact: published              │
              └────────────────────────────────────────────┘
```

The publish workflow opens a pull request to `main` so that humans review
and approve changes before they land.

## Running Workflows Manually

### Stage 1 – Generate (dry-run)

```
GitHub → Actions → [Reusable] Generate Hypergredient Primitives → Run workflow
  dry_run: true
```

This validates the pipeline without writing any files.

### Stage 2 – Refine

```
GitHub → Actions → Hypergredient Primitives – Stage 2: Refine → Run workflow
  dry_run: false   (or true for a dry run)
```

The refine workflow always calls Stage 1 internally first.

### Stage 3 – Publish

```
GitHub → Actions → Hypergredient Primitives – Stage 3: Publish → Run workflow
  dry_run: false
  pr_branch: chore/update-hypergredient-primitives
```

The publish workflow downloads the latest refined artifact and opens a PR.

## Python CLI Reference

All scripts accept `--help` for full usage.

### `generate_primitives.py`

```bash
cd examples/python
python generate_primitives.py \
  --output-root ../../metop \
  [--dry-run]
```

Writes raw primitives to `metop/hyping/<slug>/raw/<slug>.json` and a
global `metop/hyping/index.json`.

### `refine_primitives.py`

```bash
cd examples/python
python refine_primitives.py \
  --output-root ../../metop \
  [--dry-run]
```

Reads raw primitives, adds AI-scoring and evolution hooks, and writes:
- `metop/hyping/<slug>/refined/<slug>.json`
- `metop/hyping/<slug>/scored/<slug>_scored.json`

Requires Stage 1 to have run first.

### `publish_primitives.py`

```bash
cd examples/python
python publish_primitives.py \
  --output-root ../../metop \
  [--dry-run]
```

Generates Markdown reports and refreshes:
- `metop/hyping/<slug>/reports/<slug>_report.md`
- `metop/hyping/index.json`
- `metop/hyping/run_manifest.json`

Requires Stages 1 and 2 to have run first.

### `validate_primitives.py`

```bash
cd examples/python
python validate_primitives.py \
  --output-root ../../metop
```

Exits 0 on success, 1 on any validation failure.  Always run after a
pipeline stage before committing results.

## Primitive Schema

Every JSON primitive carries these top-level keys:

| Key | Stage | Description |
|---|---|---|
| `schema_version` | all | Semantic version string (`1.0.0`) |
| `pipeline_stage` | all | `raw` / `refined` / `scored` / `published` |
| `provenance` | all | Source module, timestamps, generator name |
| `identity` | all | `name`, `inci_name`, `slug` |
| `classification` | all | Hypergredient class (`H.*`), primary/secondary functions |
| `optimization_metrics` | all | Efficacy, bioavailability; synergy + confidence filled at Stage 2 |
| `safety_stability_cost` | all | Safety score, pH range, stability, cost |
| `relationships` | all | Synergies, incompatibilities |
| `ai_insights` | refined + | Ranked concerns, model version |
| `benchmark` | scored + | Multi-objective score, stability label, cost tier |

### Required fields enforced by `validate_primitives.py`

**Raw:** `schema_version`, `pipeline_stage`, `provenance`, `identity`,
`classification`, `optimization_metrics`, `safety_stability_cost`,
`relationships`

**Refined:** all raw fields + `ai_insights`

**Scored:** all refined fields + `benchmark`

## Validation and Safety Guardrails

`validate_primitives.py` enforces the following gates:

| Gate | Check |
|---|---|
| Folder structure | Each ingredient has `raw/`, `refined/`, `scored/`, `reports/` subfolders |
| Raw schema | All required fields present |
| Refined schema | All required fields present including `ai_insights` |
| Scored schema | All required fields present including `benchmark` |
| Safety score | Must be `≥ 1.0` and `≤ 10.0` |
| Confidence score | Must be present (`≥ 0.0`) |
| Drift detection | No expected ingredients missing; no unexpected directories |
| Index integrity | `index.json` entries cross-reference existing files on disk |

The validation step runs after every stage in CI and will fail the
workflow if any gate is violated.

## Troubleshooting

### "hyping root not found"

Run Stage 1 (`generate_primitives.py`) before Stages 2 or 3.

```bash
python generate_primitives.py --output-root ../../metop
```

### "raw primitive not found"

A raw file is missing for an ingredient.  Re-run Stage 1 or check that
the artifact download in the CI workflow succeeded.

### Drift errors: unexpected directory

An extra directory exists in `metop/hyping/` that is not in the
`HypergredientDatabase`.  Remove it or add the ingredient to the database.

### CI: artifact not found (Stage 2 or 3)

The Stage 2 workflow downloads the artifact uploaded by Stage 1.  If
Stage 1 failed or was not run, Stage 2 bootstraps inline.  Check the
Stage 1 logs for failures.

### Safety guardrail failure: `safety_score below minimum`

An ingredient has a very low safety score in the database.  Review the
ingredient definition in `hypergredient_framework.py` and either:
- Correct the score if it was entered incorrectly.
- Lower the `GUARDRAIL_MIN_SAFETY` threshold in `validate_primitives.py`
  after peer review.

### Test failures

Run the test suite locally:

```bash
cd examples/python
python -m unittest test_primitives_pipeline test_hypergredient_framework test_meta_optimization_engine -v
```

All 48+ tests in `test_primitives_pipeline.py` must pass before a
publish PR is reviewed.
